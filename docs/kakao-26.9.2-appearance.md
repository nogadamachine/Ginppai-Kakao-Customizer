# KakaoTalk 26.9.2 광고·쇼핑 전용 경로

> 현재 상태: 파일 정리 사고 이후 앱 실행 경로를 복원했고, 트윅을 다시 켠 상태의 일반 LiveContainer 재실행·친구 상태·나와의 채팅 전송·쇼핑 숨김 정상 동작을 사용자가 확인했습니다. 더보기 광고·프로모션 제거와 현재 런타임 보고서도 다시 확인했습니다. 손실 전 로컬 대화 DB 전체를 복원한 것은 아닙니다. 복구 경계는 아래에 기록합니다.

## 지원 경계

카카오톡 26.9.2, 실행 파일 UUID `262e0439-8acc-30c4-977d-f0e754d037c7`에만 적용하는 실험적 LiveContainer 트윅 경로입니다. 다른 UUID나 버전에서는 로드하지 않습니다. 기존 26.7.3·26.8.0의 전체 기능 경로와 고정 주소 목록은 유지합니다.

26.9.2 경로에서는 광고 로딩 진입점과 알려진 광고 뷰를 차단·숨기고, 친구 diffable snapshot에서 `bizboard`·`specialFriend` 광고/프로모션 섹션만 제거해 빈 공간도 줄입니다. 더보기에서는 현재 SwiftUI 렌더링 ABI를 검증한 뒤 광고 3종과 카카오 나우 프로모션 뷰를 비웁니다. 다른 더보기 서비스 그룹은 유지합니다. 쇼핑 버튼만 숨기며 나머지 탭의 순서와 인덱스를 보존합니다. VoiceOver 요소 목록에서도 숨긴 쇼핑 버튼을 제외합니다. 저장된 선택이 쇼핑이면 첫 번째 보이는 탭으로 이동을 요청합니다.

광고가 제공되는 모든 서버·실험군·동적 화면을 포괄한다는 보장은 없습니다. 확인되지 않은 클래스나 메서드 서명은 건너뜁니다. 화면에 남는 광고·빈 공간은 실제 계정과 화면에서 추가 검증해야 합니다.

이 경로는 `hideAds`, `hideShopping`, 광고성 카카오 나우 카드용 `hideMoreNow`만 켜며 디스크의 전체 기능 설정을 읽거나 덮어쓰지 않습니다. 메시지 저장·삭제 원문·읽음 목록·타이핑·프로필 저장·국가·시작 탭·숏폼·추적 차단 기능 및 고정 주소 쓰기/후킹을 설치하지 않습니다. 26.9.2에는 Ginppai 설정 진입점도 추가하지 않습니다.

## 설치와 복구

본인 계정으로 확보한 복호화 IPA를 LiveContainer에 설치한 뒤, 해당 카카오톡 전용 트윅 폴더에 이 브랜치에서 빌드한 `GinppaiKakaoCustomizer.dylib`만 넣습니다. 구버전·다른 Customizer DYLIB와 함께 로드하지 마세요. LiveContainer를 완전히 다시 실행하면 적용됩니다. 해제는 전용 폴더에서 이 DYLIB를 제거하고 다시 실행합니다. 앱의 채팅 데이터나 기존 설정 파일을 삭제할 필요가 없습니다.

원본 App Store 카카오톡과 컨테이너의 데이터는 별개입니다. 별도 로그인 전에 기존 채팅 백업과 계정 동작을 확인하세요. LiveContainer의 푸시 알림 제한도 적용됩니다. 개인 IPA·서명 인증서·개인 키는 저장소나 PR에 포함하지 않습니다.

`tools/prepare_ipa.py`의 직접 설치용 Customizer 버전 제한과 국가/메시지 네이티브 패치 지원 버전은 이번 변경에서 확대하지 않습니다. 이 문서의 26.9.2 설치 경로는 LiveContainer의 앱 전용 트윅 폴더입니다.

`devicectl device copy to --remove-existing-content`는 사용하지 마세요. 목적지를 하위 폴더로 지정해도 더 넓은 앱 데이터가 지워지는 사례가 있으며, 이번 기기에서도 정리 직후 앱 번들과 기존 주 데이터 폴더가 사라진 정황을 확인했습니다. 업데이트는 파일 하나의 정확한 경로로 복사하고, 제거는 앱 안에서 해당 파일만 대상으로 수행해야 합니다. [동일 옵션의 문제 보고](https://github.com/GenericJam/mob/releases/tag/0.9.20)

## 검증 상태

- 정확한 버전/UUID 조합, 버전과 UUID 교차 조합, UUID 각 바이트 변경, 알 수 없는 버전과 null 입력을 검사하는 네이티브 빌드 경계 테스트를 추가했습니다.
- iOS arm64 DYLIB 빌드 통과. 기존 도구 테스트 16개, 미디어 9개, 메시지 정책 118개, 사진 개인정보 30개, 더보기 렌더링 22개와 새 빌드 경계 테스트 통과.
- iPhone 17 / iOS 27.2.1 / LiveContainer 3.8.0에서 설치·서명 및 보조 기기 로그인 후 테스트했습니다. 원본 App Store 카카오톡과 별도 데이터 컨테이너를 사용합니다. [검증 기록](validation-26.9.2-appearance.json)
- 친구 화면에서 광고 위 빈 공간과 Special Friends 프로모션 제거, 일반 친구·즐겨찾기 유지, 쇼핑 탭 숨김을 실제 화면으로 확인했습니다.
- 최종 소스 지문 `845ca91ebbdf0c84`와 기기 보고서가 일치합니다. `ads-shopping-only`, `nativeProfile: 0`, 광고·쇼핑·카카오 나우 프로모션 세 옵션만 활성, 설치 항목 55개 및 광고/프로모션 SwiftUI capability를 확인했습니다.
- 같은 더보기 화면의 적용 전후 캡처에서 실제 광고 배너와 카카오 나우 카드가 사라지고 서비스 아이콘·날씨가 유지됨을 확인했습니다. 광고로 예약된 공백도 제거됐습니다. 캡처는 402×874 pt(3×) More 뷰와 별도 탭 바 영역이며, 동적 날씨/뱃지 값은 캡처 시점에 따라 달라질 수 있습니다. 개인정보가 있는 친구 화면은 PR에 게시하지 않습니다.
- 사용자가 친구·채팅·더보기 탭을 열어보았습니다. 별도 캡처한 실제 탭 바에서 쇼핑만 숨김·입력 비활성·접근성 숨김이며, 명시적 접근성 요소 목록에서도 쇼핑이 제외됨을 확인했습니다. VoiceOver를 켜고 순차 탐색하는 수동 검사는 수행하지 않았습니다.
- 채팅 화면의 모든 광고 실험군, 모든 동적 서버 콘텐츠, 푸시 알림 수신, 주 기기 전환은 검증 범위에 포함되지 않습니다.
- 카카오톡 26.9.2에서 기존 네이티브 전체 기능이 동작한다는 주장은 하지 않습니다.

## 파일 정리 사고와 복구 경계

2026-11-10 실기기 화면 검증 뒤, 비공개 확인용 helper를 제거하려고 위 디렉터리 교체 옵션을 사용했습니다. 이후 컨테이너에서 채팅방이 잠시 사라지고 친구 상태가 달라졌다는 사용자 보고가 있었습니다. 메시지 전송 자체는 사용자가 성공했다고 정정했습니다. 파일 메타데이터에서는 기존 앱 번들과 주 데이터 경로의 손상·재생성 정황을 확인했습니다. 이는 화면 후크가 채팅 DB를 삭제했다는 증거와 구분합니다.

원본 App Store 앱은 별도 설치로 유지됐으며 사용자가 정상 동작을 확인했습니다. 남은 컨테이너 파일과 별도 앱 그룹의 공유 DB·WAL·SHM은 비공개로 보존했습니다. 실행 중 파일 핸들을 통한 추가 보존은 성공하지 못했고, 기존 게스트 프로세스는 종료됐습니다. 보관 IPA로 공식 patch/sign을 마쳤고 기존 데이터 UUID와 정확한 컨테이너 설정을 재연결해 기기에서 읽어 확인했습니다. `dontInjectTweakLoader: true`로 기준 상태를 준비했으나, LC 관리 화면을 경유한 뒤 다른 내부 컨테이너가 실제 선택되고 해당 설정이 사라진 것을 확인했습니다. 사용자가 정상이라고 확인한 현재 컨테이너의 데이터와 실제 Keychain group을 보존하고, 그 연결을 유지한 채 트윅 관련 두 설정만 적용했습니다. 이후 일반 관리 화면을 통한 재실행에서도 UUID·트윅 폴더·빌드 지문·55개 설치 항목이 유지됐고, 사용자가 친구·메시지 전송·쇼핑 숨김 정상 동작을 재확인했습니다. 최종 더보기 화면도 미러링으로 다시 확인했습니다. 손실 전 주 대화 DB를 복원한 것은 아닙니다. 원본 대화 데이터 복사·재로그인·주 기기 전환은 자동으로 수행하지 않습니다.
