# 광고 여백과 친구 목록 상단 섹션 보완

광고 요청을 차단하고 뷰를 숨겨도 부모 목록이 예약한 행·항목·섹션 높이는 남을 수 있습니다. 기존 ‘광고와 프로모션 숨기기’ 옵션에 아래 처리를 함께 적용합니다.

## 확인된 광고 전용 뷰와 셀

- 허용 목록에 있는 광고 클래스만 크기 계산·intrinsicContentSize·systemLayoutSizeFittingSize 높이를 줄입니다.
- 광고 뷰 자체에 연결된 활성 상수 높이 제약만 0으로 바꿉니다. 부모 뷰나 다른 뷰와의 상대 제약은 수정하지 않습니다.
- 앱이 기존에 구현한 테이블 행 높이·컬렉션 항목 크기 메서드의 ABI가 맞는 경우, 실제 추적 중인 광고 셀의 높이를 0.01포인트로 줄입니다. 일반 행은 원래 계산을 호출하며 컬렉션 너비도 유지합니다.
- 목록과 셀을 약하게 추적하고 현재 indexPath를 다시 확인합니다. 재사용·이동 시 오래된 경로를 제외합니다. 갱신을 메인 큐에서 묶어 처리하고 화면 연결 및 미완료 갱신 상태를 확인합니다.
- UIKit 클래스의 높이 메서드, 전체 부모 컨테이너와 일반 친구·생일·프로필 영역은 대상에 넣지 않습니다.

## 친구 목록 상단 광고 섹션

KakaoTalk 26.8.0의 Swift 메타데이터에서 `FriendsFeedPresentation.FriendsListDataSource.SectionType`에 `bizboard`라는 별도 광고 섹션이 있음을 확인했습니다. 기존 필터는 `specialFriend`만 제거했습니다.

새 필터는 정확히 이 enum에서 `bizboard`와 `specialFriend` 식별자를 골라 표시 스냅샷의 복사본에서 제거합니다. 셀 높이만 줄이는 대신 섹션의 예약 공간을 제외하는 방법입니다. 프로필 업데이트·생일·즐겨찾기·일반 친구 및 알 수 없는 나머지 섹션의 순서와 항목을 유지합니다.

타입·개수·연관값·중복 식별자를 확인하고 복사 및 삭제 결과도 검증합니다. 예상과 다르거나 광고 숨김이 꺼져 있으면 원본을 사용합니다. 원본 스냅샷을 직접 바꾸지 않습니다.

## 검증 범위

정책 검사 8개와 실제 이름의 Swift enum → KCMessageBridge → Objective-C 스냅샷 변경 통합 검사 14개를 추가했습니다. 광고 섹션만 제거되는지, 일반 항목과 원본이 유지되는지, 반복 적용과 실패 시 원본 보존을 확인합니다.

뷰·셀 높이는 Foundation UI 대역을 사용해 구조체 ABI, 재사용, 다른 행·목록 보존, 제약 범위, 갱신 중복 억제 및 약한 참조를 검사합니다. 실제 UIKit 렌더링 검증과는 구분합니다.

사용자는 첫 여백 보완 후에도 친구 목록의 내 프로필 아래에 빈 공간이 남는다고 보고했습니다. 이후의 `bizboard` 섹션 제거 수정은 기기에서 아직 확인받지 못했습니다. 고정 부모·섹션 여백, 절대 크기를 쓰는 다른 컬렉션 레이아웃 및 미확인 광고 클래스는 추가 검증이 필요합니다.
