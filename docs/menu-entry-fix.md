# 3.0.1 메시지 메뉴 수정

## 원인

KakaoTalk 26.7.3의 제스처는 `invokeSubmenuAction:` 또는 `invokeSubmenuActionByTap:`으로 들어갑니다. 3.0.0은 `withTargetView:`를 받는 별도 메서드만 연결했습니다. 단일 인자 메서드의 Swift 구현이 내부 함수를 직접 호출하면 기존 연결을 거치지 않았습니다.

기기에서 네이티브 말풍선에 연결된 제스처의 뷰와 단일 인자 처리 경로를 사용했을 때, 3.0.0은 기본 메뉴만 표시했고 트윅의 메뉴 진입 기록은 없었습니다. 앞선 시험은 두 인자 경로를 사용해 이 결함을 놓쳤습니다.

## 수정

네 가지 메서드의 Objective-C ABI를 각각 확인하고 같은 선택 메시지 문맥 처리에 연결합니다. 중첩 호출이 끝나면 이전 문맥으로 복구합니다. 메뉴의 행 수와 높이는 바꾸지 않습니다.

## 확인 범위

- 3.0.1에서 단일 인자 길게 누르기 경로로 메시지 도구 표시와 읽은 사람 화면 진입 확인.
- 단일 인자 탭 경로에서도 도구 버튼과 선택한 메시지의 정보 일치 확인.
- 삭제된 말풍선에서 보관된 원문용 도구와 정확한 메시지 정보 표시 확인. 새 메시지 전송이나 삭제 없이 기존 시험 메시지를 사용했습니다.
- 기기 내부 시험 도구는 제스처 상태와 말풍선 뷰를 전달합니다. 사람이 손가락으로 실제 길게 누른 시험과는 구분합니다.
- 읽음 정보는 기기가 보유한 읽음 위치에 한정됩니다. 이름 자료가 없으면 이름 확인 불가로 표시합니다.
