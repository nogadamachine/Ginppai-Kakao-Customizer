# KakaoTalk 26.9.2 채널 분리와 탭 정리

## 요청 범위와 완료 조건

이번 변경은 `262e0439-8acc-30c4-977d-f0e754d037c7` 실행 파일과 기존 LiveContainer 설치를 대상으로 합니다. 이전 광고·쇼핑 변경은 PR #1에서 병합됐으며, 이 요청은 별도 변경으로 검증합니다.

| 영역 | 요청한 결과 | 확인할 동작 |
|---|---|---|
| 친구 | 친구/소식을 친구/채널로 바꾸고 채널 목록을 분리 | 일반 채팅과 같은 개별 캡슐 칩, 친구에 채널 집계 행이 없고 채널 목록·프로필 진입이 유지됨 |
| 일반 채팅 | 광고 예약 공백과 채널 발신 대화를 제외 | 개인·그룹·나와의 채팅, 사용자 폴더·정렬·열기·전송 유지 |
| 세 번째 탭 | 오픈채팅·채널채팅·조용한 채팅, 숏폼·커뮤니티 제외 | 개별 캡슐 칩, 각 목록 상태·내부 unread·채팅 열기/뒤로 가기 유지 |
| 오픈채팅 | 광고·추천 방·공백·커뮤니티 진입점 제거 | 가입한 오픈채팅과 필요한 오류·제재 설명은 보존 |
| 배지 | 오픈/채널 배지는 내부에만 표시 | 앱 아이콘·하단 탭에서 제외하고 일반 채팅 배지는 유지, 읽음 상태를 변경하지 않음 |
| 더보기 | 홈/게임 선택 영역을 없애고 홈 내용만 유지 | 저장된 게임 선택에서도 홈으로 복귀, 서비스·날씨 유지 |

## 구현·데이터 경계

- 기존 계정, 실제 사용 중인 데이터 UUID/Keychain group, 앱 bundle ID를 보존합니다. 재로그인·초기화·주 기기 전환을 하지 않습니다.
- 채널 구분은 네이티브 predicate/정확한 enum 모델을 확인해 사용합니다. 표시 이름, 메시지 문구, ID 부호, 친구 채널 목록 멤버십으로 대화 종류를 추측하지 않습니다.
- 표시용 snapshot/컨트롤러와 배지 소비 위치만 바꿉니다. 대화 삭제, 숨김 플래그·읽음 수·친구 관계의 영속 저장은 수행하지 않습니다.
- 네이티브 화면은 생성자·의존성·선택 callback·containment를 검증한 후 재사용합니다. Swift protocol slot이나 다른 signature의 closure를 포인터로 대입하지 않습니다.
- 조용한 채팅은 기존 Archive 화면과 선택·편집 핸들러를 재사용합니다. 새 화면의 데이터 준비를 확인한 뒤 일반 목록에서 실제 `SilentChat` entity만 native `excludingEntity` predicate로 제외합니다. 실제 보관된 대화나 보관 상태를 변경하지 않습니다.
- 배지 제외 getter는 네이티브 snapshot 생성의 네 return-PC에만 적용합니다. 같은 getter를 사용하는 네이티브 저장/갱신 판단은 원래 결과를 유지합니다. 내부 Open unread publisher도 유지합니다.
- 알 수 없는 타입/ABI/분류는 원래 동작을 유지합니다. 기존 26.7.3/26.8.0의 전체 기능 경로를 활성화하지 않습니다.
- 배포는 개인 검증 기기의 앱 전용 트윅 파일 단위로 수행합니다. `devicectl --remove-existing-content`와 디렉터리 교체·정리 명령을 사용하지 않습니다. 이전 정상 DYLIB와 데이터 사본을 보존합니다.

## 실기기에서 확인한 수정 사항

iPhone 17 / LiveContainer에서 로그와 화면으로 확인한 문제와 수정입니다.

- **채널채팅·조용한 채팅이 눌리지 않음**: 채널 라우팅 코디네이터를 채팅 탭이 로드될 때만 잡았습니다. 다른 탭에서 시작하면 비어 있어 같은 탭 바에서 찾아 가져오도록 했습니다.
- **전환 시 화면이 54pt 내려감**: 네이티브 pane이 내비게이션 바를 다시 보이게 해 상단 안전 영역이 62에서 116으로 늘었습니다. 최초 상태를 기억해 두었다가 복원합니다. pane 스크롤뷰의 상단 inset도 0으로 고정합니다.
- **세 번째 탭 진입 시 깜빡임**: 광고 행을 걸러낸 snapshot은 애니메이션 없이 적용합니다. 숏폼/브랜드로 돌아가는 순간은 배경색 커버로 가립니다.
- **더보기 상단 빈 공간**: 선택 칩을 접어도 SwiftUI 콘텐츠가 그 높이를 유지했습니다. 패딩 설정을 레이아웃 도중이 아니라 다음 run-loop에서 적용해야 SwiftUI가 반영합니다. 보정량은 접은 칩의 실제 높이(50pt)로 계산합니다.
- **선택된 탭 재클릭**: 모든 탭에서 이미 선택된 탭을 다시 눌러 내부 탭이 바뀌는 동작을 무시합니다. 다른 탭에서 들어오는 동작은 그대로입니다.

## 발견한 구조와 아직 필요한 증거

원본 main SHA-256: `4890657f3a2141e3c7c09cc3427b1d789ebe5997467fc451457a433c8bb81a2b`.

- Friends의 `.category(.plusFriend)` 집계 행과 네이티브 MyPlusFriends 목록이 있습니다. Friends의 두 번째 slot은 private Swift protocol이므로 일반 VC 직접 대입은 하지 않습니다.
- 일반 채팅·오픈채팅·채널 채팅은 서로 다른 정확한 section/item enum을 사용합니다. 광고·추천만 복사 snapshot에서 제외하고 실제 대화·오류 상태를 보존할 경계가 있습니다.
- ChannelChats VC/VM 및 ChatFolderContentCoordinator에 기존 라우팅이 있습니다. 기본 생성자 존재와 실제 callback 연결은 별도로 검증합니다.
- 네이티브 Channel/Partner predicate와 app/open-chat 배지 제외 모델이 있습니다. 실제 사용 모델·합산 단위·mute 설정은 런타임 검증 전까지 미확인입니다.
- More의 정확한 `.home` identifier를 선택한 후 chip 영역을 접어야 합니다. 선택기만 숨겨 게임 내용이 남게 하지 않습니다.

이 문서의 발견 사항은 정적 구조 증거입니다. 런타임 UI·메시지 전송·배지 검증 결과와 실제 전후 캡처는 구현 후 갱신합니다. 개인 연락처·메시지·IPA·키·DB 사본은 PR에 포함하지 않습니다.
